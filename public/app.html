Which input on that device
Input in this browser

The browser captures the sound and sends it here, so this machine needs no ffmpeg and no device names typed exactly right. It captures from whichever machine has this page open, and the page must stay open for the whole service.

So this cannot be driven from somewhere else: open it on a laptop and it captures that laptop, not the mixer plugged into the bridge. To run a service from another machine, use an audio device on this machine above and pick the input there.

Recording to play

Played at the speed it was recorded, so the delays behave exactly as they would live. Costs Soniox time like a real service does — stop when you have seen enough.

Sound coming in

The bar moves when someone is speaking. If it stays flat, the cable is not carrying sound.

Pause stops listening but lets everything already spoken finish going out — it does not throw away the minutes still waiting. End session stops everything at once: the queue is discarded, the screens go blank, and a recording being played in stops playing.

Screens

Words have to be drawn to appear in a picture. Each of these is a web page with a transparent background showing the line that is current right now — open one as a vMix Browser input and lay it over the video. One page per destination, because each gets different words at a different moment.

YouTube captions do not use these. They are sent to YouTube as text and the viewer switches them on, so there is no page to point anything at. YouTube hands you that URL when you switch the stream's captions to "POST to URL"; it goes in Settings → Keys and passwords.
